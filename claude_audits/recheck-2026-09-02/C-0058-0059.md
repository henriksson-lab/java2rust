# 0058 — class upcast discards the object; `super.m()` returns `Default`; `instanceof` is exact-type

## VERDICT: **PARTIALLY FIXED**

- `super.m()` is genuinely **FIXED** — real superclass dispatch, matches Java.
- Upcast and supertype-`instanceof` are **FIXED for the silent-wrong-answer complaint**
  (they now emit `compile_error!`) but the underlying feature is **NOT FIXED**: there is
  still no class-hierarchy carrier, so those programs do not compile at all.
- **Nothing in the 0002b shared-representation design is doing this work.** The mechanisms
  that landed are (a) a refusal guard on the source-subtype→supertype conversion path, and
  (b) a direct call to the emitted superclass inherent impl with a field-copied temporary.
  Both are local, not a representation change. The one place the object model *did* change
  (an erased-object alias for the `instanceof` target class) introduces a new syntax error —
  see D1 below.
- **2 new adjacent defects found** (D1, D2).

## New adjacent defects — 0058

### D1 (new, blocking): nested class forced onto the erased-object carrier emits an unmangled dotted `pub type`

The `instanceof`-with-subtypes path represents the target class as an erased-object alias, and
that alias is emitted with the **Java dotted name**, which is not a Rust identifier. It is a
parse error, so it takes down the whole file before any other diagnostic is reachable — 0013 at
a third site (the type-alias emitter, not the downcast or the `dyn` coercion).

Minimal repro `mini/AliasMin.java`:

```java
public class AliasMin {
    static class A {}
    static class B extends A {}
    static boolean isA(Object o) { return o instanceof A; }
    public static String run() { return "" + isA(new B()); }
    public static void main(String[] args) { System.out.println(run()); }
}
```

Generated (lines 2762-2764):

```rust
pub type AliasMin.A = Box<dyn std::any::Any>;

pub type A = AliasMin_A;
```

Two problems on three lines: the first alias is a syntax error, and `AliasMin_A` — referenced
by the second alias and by `impl From<AliasMin_B> for AliasMin_A` at line 2777 — is never
defined under that name. Renaming the alias by hand (`sed 's/^pub type AliasMin\.A = /pub type AliasMin_A = /'`)
makes the file compile down to exactly one error, the intended one:

```
error: unsupported Java instanceof shape: actual=ErasedObject, target=ErasedObject
    --> mini/AliasMinFixed.rs:2792:16
error: aborting due to 1 previous error; 77 warnings emitted
```

So D1 is separable from the open carrier gap and is a pure name-mangling bug.

The declaration-only variant (`mini/AliasMin2.java`: same classes, `Object o = new B()`, no
`instanceof`) does **not** trigger it — only the erased-carrier path does.

### D2 (new): a mutating `super.m()` gets a `&`-borrowed temporary and would lose the mutation

The field-copy temporary that fixed §2 is read-only. When the super method mutates base state
the generated call passes `&Base { .. }` to a `&mut self` method — E0308 — and even if the
borrow matched, the write would land on a discarded temporary.

Minimal repro `mini/SuperMutate.java`:

```java
public class SuperMutate {
    static class Base {
        int n;
        Base(int n) { this.n = n; }
        void bump() { this.n = this.n + 1; }
    }
    static class Derived extends Base {
        Derived(int n) { super(n); }
        void bump() { super.bump(); this.n = this.n + 10; }
    }
    public static String run() { Derived d = new Derived(1); d.bump(); return "" + d.n; }
    public static void main(String[] args) { System.out.println(run()); }
}
```

Java prints `12`. Generated:

```rust
    pub fn bump(&mut self) {
        SuperMutate_Base::bump(&SuperMutate_Base { n: self.n });
        self.n = (self.n).wrapping_add(10);
    }
```

```
error[E0308]: mismatched types
2787 |         SuperMutate_Base::bump(&SuperMutate_Base { n: self.n });
```

Loud, so not a silent wrong answer, but it marks the boundary of the §2 fix: `super.m()` works
only for super methods that do not write to `this`.
