## Finding A — the one "never finished" piece that was deleted and is still not finished

**Item 1 is only two-thirds fixed, and the missing third is now a runtime `panic!`
in generated Rust rather than an unimplemented descriptor in `src/`.**

The audit deleted `DynCloneBoxAdapter*` on the grounds that the production path had
moved to a reachable `DispatchCoercionPolicy::CloneBoxDynTrait`. That producer is
real (`conversion_plan.rs:1855` constructs it; `coercion.rs:13688` renders
`.clone_box()`). What the deleted design deferred — *generating the adapter that
makes `clone_box()` work* — is still deferred. The only `clone_box` body emitted for
a plain source-class carrier is:

```rust
// src/representation_lowering.rs:1016-1021
fn trait_object_support_impl_methods(trait_name: &str) -> Vec<String> {
    vec![
        "    fn as_any(&self) -> &dyn std::any::Any { self }".to_string(),
        format!(
            "    fn clone_box(&self) -> std::boxed::Box<dyn {trait_name}> {{ panic!(\"java2rust: clone_box for {trait_name} requires a cloneable Java object carrier\") }}"
        ),
    ]
}
```

and the tests assert exactly that spelling:

```
tests/slot_shape_design.rs:6038:
"impl Named for Dog {\n … fn clone_box(&self) -> std::boxed::Box<dyn Named> { panic!(\"java2rust: clone_box for Named requires a cloneable Java object carrier\") }\n}"
```

Only the shared-handle forwarding impls (`impl<T: Named> Named for Rc<T>`) emit a
working `Box::new(self.clone())`. So a `&dyn T` reaching an owned `Box<dyn T>` slot
whose carrier is a bare source struct now compiles and panics at run time. The audit
names this ("the remaining live risk is whether every generated dyn trait actually
has a valid `clone_box()` surface") but files it as out of scope; it belongs on the
outstanding list, because the deletion removed the design record and the replacement
is a panic.
